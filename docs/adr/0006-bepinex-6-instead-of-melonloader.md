# ADR-0006 — BepInEx 6 (be.785) instead of MelonLoader

- **Status:** accepted (decided by the user on 2026-11-07)
- **Date:** 2026-11-07
- **Decides:** which loader runs the mods
- **Supersedes:** the MelonLoader part of
  [ADR-0001](0001-melonloader-net6-and-host-gate.md). `net6.0` and lint in the build still
  apply.

## Context

- On the game's official Discord people share
  [Disfigure-Mod-Manager](https://github.com/Purpledudr/Disfigure-Mod-Manager): a program
  that installs **BepInEx 6.0.0-be.785** (Unity IL2CPP, win-x64) and manages plugins from a
  `plugins.json` catalog. The translation mod, sandbox mode and an optimization mod are
  published there. The game's modding community uses BepInEx.
- Its `DisfigureTranslationMod.csproj` is set up like our mods: `net6.0`, references to the
  local install with `Private=false` (`BepInEx\core` and `BepInEx\interop`), Harmony and
  `UnityEngine.IMGUIModule`. Its package with BepInEx bundled passed a clean-install launch
  test on Windows x64, so be.785 works with this game version (Unity 6000.3.16f1, metadata
  v39).
- MelonLoader and BepInEx hook into the game the same way (a proxy DLL in the game folder:
  `version.dll` for one, `winhttp.dll` for the other). Installed together, they load both
  runtimes in the same process. For the mod to live alongside the community plugins, it has
  to be a BepInEx plugin.
- The mod code that reads the game is pure Il2CppInterop, the same on both loaders. Little
  depends on MelonLoader: the base class (`MelonMod`), the `OnUpdate` and `OnGUI` callbacks,
  and the logger.

## Decision

- Mods are loaded with **BepInEx 6.0.0-be.785, Unity IL2CPP, win-x64**: the same build
  Disfigure-Mod-Manager installs. MelonLoader is removed from the game.
- Each mod is a `BasePlugin` with `[BepInPlugin]`. `Update` and `OnGUI` go in an own
  `MonoBehaviour` the plugin registers in IL2CPP with `AddComponent<T>()`.
- References come from `BepInEx\core` and `BepInEx\interop` of the local install, with
  `Private=false`, as before.
- Each mod is deployed to `BepInEx\plugins\<mod name>\`, and its log goes to
  `BepInEx\LogOutput.log`.
- Development does not depend on Disfigure-Mod-Manager. To get listed there, the author is
  offered an entry for their `plugins.json`.

## Consequences

**Pros:** the mod can live alongside the plugins the community uses, and can be distributed
the same way.

**Cons:**

- BepInEx 6 is still in "bleeding edge" builds, with no stable release.
- The interop assemblies are regenerated by BepInEx, and everything that already worked
  with MelonLoader has to be checked again in the game.
- Game type names can change: MelonLoader added the `Il2Cpp.` namespace prefix.

**Revisit if:** be.785 stops working after a game update, or the community moves to another
loader.

## Alternatives considered

- **Stay on MelonLoader:** it works, but the mod could not live alongside the BepInEx
  plugins the community uses.
- **Support both loaders from the same code:** doubles the entry class, the deployment and
  the in-game checks, for an audience that is already on BepInEx.
- **A BepInEx build newer than be.785:** another combination untested with the game. be.785
  is the one the community already uses.
